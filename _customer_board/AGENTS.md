# Customer Board ticket workflow

- 고객이 등록한 ERP·ORD 요청은 독립적으로 재현하고 검증할 수 있는 단일 티켓으로 유지하고, 모두 `고객보드`와 `자동분류-미확정` 라벨로 접수한다.
- `자동분류-미확정`은 ORD의 재발/단발 구분이 아니라 ERP·ORD 공통의 티어 확정 전 안전 상태다.
- ANACO-3 야간 워커는 자동 진단과 질의 초안 생성을 계속 수행한다. 이 워커나 예약 작업을 임의로 끄거나 삭제하지 않는다.
- 모든 Tier 티켓은 개발자에게 자동 배정한다. Tier 1도 자동수정하지 않으며 담당 개발자가 AI 코딩 에이전트로 처리한다.
- 배정 풀의 활성 Linear 계정이 하나라도 확인되지 않으면 임의 계정으로 대신 배정하지 않고 안전하게 대기한다.
- 개발 완료는 새 QA 티켓을 만들지 않는다. 같은 티켓을 `QA Request`로 전환하면 QA 담당자를 자동 배정하되 상태는 유지하고, 담당자가 착수할 때 `QA In Progress`로 변경한다. 내부 QA 통과는 `Done`, 반려는 원 개발자에게 재배정 후 `In Progress`다.
- 고객 검수는 개별 티켓 상태로 관리하지 않는다. 모듈·마일스톤 단위 `[최종검수]` 후 나온 고객 피드백은 기존 `Done` 티켓을 재개하지 않고 새 티켓으로 등록한다.
- 작업을 시작할 때 화면코드와 증상 키워드로 관련 과거 티켓을 검색할 수 있다. 검색 결과는 구현·회귀 테스트의 참고 문맥일 뿐, 재발 여부를 자동 판정하거나 티켓을 병합·종료하는 근거로 사용하지 않는다.
- 재현, 수정 범위 결정, 검증, PR/배포 판단은 선택한 티켓 단위로 수행한다.
- 웹발주 화면과 이슈의 시스템 프리픽스는 `[WEB]`이 아니라 `[ORD]`를 사용한다.
